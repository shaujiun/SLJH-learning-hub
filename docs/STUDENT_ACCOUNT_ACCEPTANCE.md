# 學生帳號與學習進度驗收

更新日期：2026-11-21

## 驗收原則

這份驗收將「程式測試」、「正式資料稽核」及「真實裝置操作」分開記錄。程式已部署或資料表存在，不等於學生實際操作已通過。

## 已通過

### 正式資料稽核

- 有效且已核准的學生帳號共 20 個。
- 數學分組為 A 組 7 人、B 組 13 人；英語分組為 A 組 7 人、B 組 13 人。
- 數學與英語分組均無遺漏、重疊、互相衝突或無效代碼。
- 本週每日任務共 11 筆，任務分組與學生目前分組不一致為 0 筆。
- 教師或管理者紀錄混入學生統一進度為 0 筆。
- 重複作答識別碼為 0 筆。
- 作答明細與彙整進度不一致為 0 筆。
- 學生作答與彙整資料表均有「本人讀取」及「管理者讀取」政策。

### 程式自動化驗收

- 共同、數學 A／B 組、英語 A／B 組入口的可見性判斷正確。
- 因式交鋒：訪客預設為 B 組基礎題，學生依數學分組直接進入對應難度，且不能自行換組。
- 因式交鋒：教師與管理者只能試玩，不會寫入學生紀錄。
- 畢氏定理挑戰賽：學生依數學分組進入對應題目，每日任務可正確送出。
- 英語閱讀：訪客不可讀取、學生須通過帳號檢核、管理者可預覽、分組查詢失敗時不會默認成 B 組。
- 統一學習進度：未登入不寫入，管理者沒有學生身分時會略過，不污染學生進度。
- 全專案 109 個測試檔、580 項測試全部通過，正式建置成功。

### 已由使用者確認

- 同一學生帳號在筆電完成任務後，手機可看見完成紀錄，跨裝置同步正常。

## 尚待真實帳號或裝置驗收

- 以一個 A 組學生及一個 B 組學生實際登入，逐項確認各遊戲內的題目難度與提示內容。
- 以教師、管理者及學生帳號實際確認可進入區塊與可操作功能。
- 在手機、平板與電腦分別完成一次任務，確認版面、送出及重新登入後的狀態。
- 對每個會計入每日任務的遊戲各測一次：完成、重玩、作答中離開、重新進入、跨裝置接續。
- 成語填字圖修正後，需由學生重新完成一題，確認新的統一作答紀錄已產生。

## 目前限制與風險

- 正式站目前 7 個啟用中的學習系統，`audience_scope` 都是 `common`。因此可以用自動化測試確認 A／B 組判斷，但無法在正式站驗證「A 組限定入口」與「B 組限定入口」的實際顯示差異。
- `learning_systems` 與 `learning_activities` 目前允許已登入者讀取，再由前端隱藏不符合分組的入口。未來若真的啟用 A／B 組限定入口，應再評估是否改成資料庫端直接過濾。
- 歷史科系統目前啟用，但沒有啟用中的活動。若歷史科只作為瀏覽入口，這是合理狀態；若應有每日任務或練習活動，需另行補設。
- 尚未完成平板實機驗收；在完成前不得把「手機與電腦正常」推論成「所有裝置正常」。

## 完成標準

第三優先只有在上述真實帳號與裝置項目都有結果，且失敗項目完成修正與複測後，才標記為完成。
